# 前端需求符合性审查

当前前端实现的是 Phase 1 的 Mock 演示，而不是可与后端共同验收的 MVP。AM 登记、BO 审阅派发和 DS 只读任务页面已有基本界面，但附件、真实接口联调、数据契约和核心交付闭环均未完成。Phase 2 至 Phase 4 的前端任务，包括版本、客户评审、交付、看板、时间线、异常和站内提醒，尚无实现。**Watch for:** **confirmed** 当前构建固定使用 Mock；**confirmed** BO 队列在接入真实后端后会请求仅授权 AM 的接口；**confirmed** 订单登记不支持必填附件，无法满足最小闭环入口。  
**Verdict**: NEEDS_CHANGES

## High-level view

路由、Pinia 会话和三角色页面骨架已经覆盖了 Phase 1 的主要入口，且路由守卫会在前端阻止角色不匹配的路径访问。**likely** 这只是体验层门禁，不能替代后端的 JWT、接口授权和资源可见性校验，且当前 Mock 模式使真实联调没有发生。

AM 创建订单支持多条物料规格及表单必填校验，但附件区明确是占位内容。**confirmed** 由于提交入口没有附件选择、上传和关联能力，订单无法满足 AM-02、PRD M1 及提交前至少一个附件的约束。

BO 的审阅和派发界面可演示退回与创建任务。**confirmed** 待审阅列表复用了 AM 专用接口，派发请求又把被派发人固定为 ID 3，导致真实环境会出现授权失败或任务分配给错误人员。

DS 页面仅显示任务自身字段。**confirmed** 任务详情没有需求基线、参考素材下载、版本交付或反馈区域，因而既未完整完成 DS-01，也未开始 Phase 2/3 的后续链路。

## 发现（按严重度排序）

### 阻断

1. **[confirmed] 前端永久走 Mock，未完成 P1-T33 联调。** `USE_MOCK` 固定为 `true`，全部 API 调用会被自定义 adapter 拦截；Mock 数据存于浏览器 `localStorage`，并非真实 API、数据库或对象存储。任何关于鉴权、审计、数据可见性、状态机和文件直传的验收都不能从当前运行结果成立。应删除固定开关或改为受环境配置控制，并完成针对真实后端的联调和端到端测试。见 `frontend/src/api/http.ts:16,47-49`、`frontend/src/api/mock-data.ts:55-60`。

2. **[confirmed] 必填参考素材无法上传，登记提交违反 AM-02、M1、BR-01 与任务 P1-T26/P1-T27。** 创建页把附件区明确标为“待实现”，没有 `input[type=file]`、预签名 URL 获取、对象存储 PUT、上传进度或元数据确认；提交请求也不含附件关联信息。任务文档要求提交前至少关联一个附件，现有页面却允许并实际创建空附件订单。应实现 P1-T26 的直传组件，在提交前校验并关联至少一个成功上传的附件。见 `frontend/src/views/am/CreateOrder.vue:2-4,101-102,205-211`、`frontend/src/api/modules/order.ts:7-13`、`frontend/src/api/mock-data.ts:254`。

3. **[confirmed] BO 待审阅队列调用 AM 专用的 A-24 接口，接入真实后端后不能工作。** `PendingReviewList` 调用 `orderApi.listMyOrders()`，该函数请求 `/orders/mine`；任务定义明确 A-24 仅供 AM，后端控制器也要求 `hasRole('AM')`。Mock 为 BO 放宽返回全部订单掩盖了契约错误。应提供 BO 待审阅队列 API 并在页面改用它，或由后端正式定义该接口可供 BO 调用并补齐类型、鉴权和测试。见 `frontend/src/views/bo/PendingReviewList.vue:5-8,30-33`、`frontend/src/api/modules/order.ts:67-69`、`frontend/src/api/mock-data.ts:201-206`。

4. **[confirmed] 派发人姓名与身份不一致，任务总是写给 ID 3。** 两个 BO 派发入口均允许任意输入设计师姓名，却将 `assignee_id` 常量传为 `3`。界面显示的姓名可与实际被派发账户不同，造成责任人、DS 待办和后端审计错误。应以受权限控制的 DS 用户列表选择真实 `assignee_id`，并移除自由输入与硬编码。见 `frontend/src/views/bo/OrderReview.vue:96-103,206-211`、`frontend/src/views/OrderDetail.vue:135-142`。

5. **[confirmed] Phase 2–4 前端交付均缺失，MVP 闭环不能完成。** 现有 API 模块只有订单和只读物料任务；没有设计版本上传/提交/对比/放行/退回、客户评审与反馈、客户确认/终稿/交付/归档、看板、时间线、异常或通知实现。应按 P2-T12–T15、P3-T09–T13、P4-T12–T16 实现并在真实接口可用后联调。见 `frontend/src/api/modules/order.ts:40-80`、`frontend/src/api/modules/materialTask.ts:22-33`、`frontend/src/views/ds/TaskDetail.vue:3-10,84-88`。

### 高

6. **[confirmed] “保存草稿”把订单创建为待审阅，绕过 AM-03 的提交动作。** 保存草稿直接调用 `createOrder`；Mock 创建时即设为 `PENDING_CONFIRM`，而 BO 队列以该状态筛选，所以未经“提交并送审”的订单会出现在 BO 待办。需求文档虽未定义可持久化的 `DRAFT` 状态，却要求只有提交触发 BO 审阅；应删除该按钮，或明确并实现独立草稿模型/状态，使其不会进入待审阅队列。见 `frontend/src/views/am/CreateOrder.vue:126-143,238-241`、`frontend/src/api/mock-data.ts:239-257`、`frontend/src/views/bo/PendingReviewList.vue:22-25`。

7. **[confirmed] DS 任务详情缺少需求基线和参考素材，未满足 DS-01。** 页面只请求并展示 `TaskDetail` 的任务属性，类型中没有需求基线或附件字段，页面也没有下载入口。设计人员无法在任务内查看完整需求与参考文件。应扩展 S-06 响应和页面，显示冻结的 `RequirementBaseline`、附件列表及受鉴权下载操作。见 `frontend/src/api/modules/materialTask.ts:6-20`、`frontend/src/views/ds/TaskDetail.vue:38-47,60-88`。

8. **[confirmed] 订单详情仅列出附件，不能下载，未完成 AM-02、BO-01、DS-01 和 P1-T29。** 附件列表只是文件名与大小文本，未调用 S-08，也没有可操作的链接或按钮。应封装附件下载 API，并以浏览器跳转处理后端鉴权后的限时下载地址。见 `frontend/src/views/OrderDetail.vue:246-256`、`frontend/src/views/bo/OrderReview.vue:176-187`、`frontend/src/api/modules/order.ts:40-80`。

9. **[confirmed] 401 刷新逻辑会让首个失败请求永久等待，并且按统一响应包装读取 token 时可能写入 `undefined`。** 刷新成功后代码先清空并执行等待队列，随后才把当前失败请求加入队列，因此该请求没有回调触发；刷新调用还绕过 `http` 实例，并按顶层 `access_token` 读取，与本文件声明的 `{ data: ... }` 包装不一致。应把当前请求先入队或直接重放，采用同一响应契约读取 `data.access_token`，并补充并发 401、刷新失败和重放失败测试。见 `frontend/src/api/http.ts:98-105,113-123`。

10. **[confirmed] 当前项目没有前端自动化测试，构建也无法在审查环境执行。** 搜索不到测试文件或测试脚本，`package.json` 仅提供 dev/build/preview；任务要求的路由守卫、上传重试、分页、RBAC 和端到端验收没有证据。尝试 `npm run build` 与 `npm.cmd run build` 均失败，后者明确提示找不到 `vue-tsc`，说明依赖未安装或安装不完整。应恢复可复现的依赖安装，补充单元/组件/E2E 测试并在 CI 执行。见 `frontend/package.json:5-8`。

### 中

11. **[confirmed] 列表分页、筛选和窄屏单列布局未实现。** AM 列表一次性显示全部 `res.data`，没有游标参数、`has_next`/`next_cursor` 处理或筛选控件；BO 待审阅页也仅在内存中过滤。各详情页及 BO 操作面板固定两列，未定义 `1024px` 以下的页面级单列规则。应按 NFR-P2、M7、P1-T28、P1-T30 和 NFR-U2 实现服务端游标分页、筛选及响应式断点。见 `frontend/src/views/am/MyOrderList.vue:14-25,45-86`、`frontend/src/views/bo/PendingReviewList.vue:5-8,22-25`、`frontend/src/views/bo/OrderReview.vue:263,285`、`frontend/src/views/OrderDetail.vue:360-362`。
