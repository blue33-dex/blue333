## 1. 使用说明

本日志记录审查中发现的前端需求偏差、建议修改内容和验收标准。除明确标记为“已完成”的项目外，所有条目均为**待整改**，并非代码已经修改的记录。

整改顺序遵循任务文档的阶段依赖：先完成并联调 Phase 1，再依次实施 Phase 2、Phase 3 与 Phase 4。不得将后续阶段功能前置到尚未验收的前置阶段。

## 2. 当前已具备的能力

- Vue 3、Vite、TypeScript、Pinia、Vue Router 项目骨架。
- 登录页和 AM、BO、DS 三类路由入口。
- 前端路由角色守卫及 403 页面。
- AM 创建订单表单，支持物料规格动态增删和基本必填校验。
- AM 我的订单列表和订单详情基础展示。
- BO 待审阅列表、审阅详情、退回和派发的 Mock 界面。
- DS 我的任务列表、截止倒计时和只读任务详情。
- Mock 层对 AM、DS 的部分数据可见性模拟。

## 7. 安全、数据与性能验证边界

以下项不能只依靠当前前端代码证明，必须通过真实后端、对象存储和联调测试验证：

- JWT 签发、刷新令牌轮换、Token 失效和真实 401/403 响应。
- 接口级 RBAC、资源级数据可见性隔离和审计日志不可篡改。
- 用户输入的服务端 XSS 清洗与敏感信息脱敏。
- 需求基线冻结、双状态机、订单完成条件、取消级联、异常关闭前置条件。
- 文件格式、200MB 大小限制、预签名 URL 过期、对象存储永久留存和孤儿文件清理。
- 看板、订单详情、首屏及文件上传性能指标。

前端当前未发现 `v-html` 使用，动态内容通过 Vue 插值渲染；这只能表明页面层未发现直接 HTML 注入点，不能替代服务端 XSS 清洗要求。

## 8. 构建与依赖状态

2026-11-02 尝试在 `frontend` 下执行生产构建，结果如下：

```text
vue-tsc -b && vite build
'vue-tsc' 不是内部或外部命令，也不是可运行的程序
```

`frontend/package.json` 已声明 `vue-tsc` 开发依赖。该错误表明本地依赖尚未安装或不完整。建议在 `frontend` 目录使用以下命令恢复依赖并验证：

```powershell
npm.cmd install
npm.cmd run build
```

PowerShell 执行策略会阻止直接调用 `npm.ps1` 时，应使用 `npm.cmd`。

## 9. 建议整改顺序

1. 恢复前端依赖并确保 `npm.cmd run build` 通过。
2. 完成 FE-P1-01 ～ FE-P1-04，先恢复可真实联调的主路径。
3. 完成附件上传、附件下载、DS 需求上下文、分页筛选和确认交互。

5. 按任务依赖顺序实现 Phase 3 客户评审与交付、Phase 4 看板/时间线/异常/通知。
6. 每个阶段完成后执行对应端到端验收，并将实际完成日期、提交记录和验证结果追加到本日志。
